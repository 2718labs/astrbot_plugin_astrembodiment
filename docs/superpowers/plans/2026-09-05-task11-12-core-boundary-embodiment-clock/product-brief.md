# AstrEmbodiment Core Boundary and Embodiment Clock

## Goal

Return AstrEmbodiment to its original role: a durable emotion, personality and
embodied-time core for each persona. Inbound semantic appraisal may still use an
LLM; the background clock must be deterministic and free of Provider, Token,
network and send work.

## Scope

Included:

- emotion, personality, allostasis, sleep and persona-local embodied time;
- Persona Genesis and the 15D to nine-region to 16K x 8 matrix;
- a Store-owned inbound observation and optional one-shot semantic appraisal;
- a typed fact for AstrBot's ordinary reply outcome;
- a permanent authenticated v9 boundary over preserved legacy autonomy data;
- a one-task adaptive Host clock with per-persona profile, timezone and sleep;
- Windows/Linux artifacts proven to come from one clean source SHA.

Excluded permanently:

- proactive contact intent or proactive chat;
- externalization, recipient/target/secret selection, outbox, dispatch or retry;
- relation scheduling, message-consent execution and unanswered backoff;
- any dependency on AstrCyberHuman;
- deletion or rewriting of old DB rows, saved settings, ciphertext or key files.

## Direction

Use an immutable v9 overlay to express the effective retirement of legacy
outbound state while leaving its physical bytes unchanged. New inbound,
ordinary-delivery and clock mutations are persona-scoped, Store-revision-bound
and idempotent.

The clock persists one authenticated head and at most 64 exact recent receipts.
It computes continuous sleep, circadian and matrix state analytically, but
writes no background row to the existing persona journal or semantic history.
The five-minute, one-hour and six-hour intervals are polling ceilings, not
mutation cadences.

Settings stay small: clock enabled, persona timezone, one auto/fixed sleep
object, and the existing inbound semantic-appraisal budget. Old proactive keys
remain preserved and ignored.

## Risk Gate

Stop rather than proceed if an implementation would:

- update, settle, rename, delete or decrypt a legacy retired row or key file;
- permit a v8/current-version migration helper to write on exact-v9 reopen;
- call a Provider, network, target, secret or send path from the clock;
- expose a generic operation that can bypass the typed core boundary;
- package wheels from different source/API/schema/tzdb identities;
- require AstrCyberHuman to make the retained core work.

## Done

The product is done only when focused migration, replay, clock and negative
surface gates pass; all affected layers compile/import; saved-data fixtures are
byte-identical; and real Windows and Linux wheels from the same clean SHA import
before the universal ZIP is assembled.
